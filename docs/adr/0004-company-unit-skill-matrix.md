# ADR-0004: taimei を事業所単位で運用する toB サービスに作り直し、最初のドメインを星取表にする

- **Status**: Accepted
- **Date**: 2026-10-05
- **References**: 非公開の PRD「taimei を事業所単位で運用する toB サービス」(2026-10-04)、taimei-auth ADR-0006 (SDK 3.1.0 の `SessionData.role`)

## Context

taimei-auth は事業所・membership・role・招待を持つが、taimei の既存ドメイン (invoice ほか) は Next.js Learn のチュートリアルが出発点で、製品ではなかった。事業所単位でサービスを運用できるかを確かめる製品が無い。invoice ドメインは #556 と #557 で消した。

## Decision

- **肝**: taimei-auth の事業所・membership・role・招待で、toB サービスを運用できること。ドメインはその上に載せるもので、事業所の仕組みを使い切るもの (全メンバーがログインする、role で操作が変わる、メンバー単位のデータを持つ) を選ぶ
- **成功の定義**: toB の事業として、既存の似たサービスより少し良いもの。判定に使う製品の KPI は、星取表を実際に使ってもらった後に決める
- **最初のドメイン**: チームの星取表。メンバー全員がログインして自分の行を書き、管理者がチームとスキルを管理するので、事業所の仕組みを使い切る。表計算でも作れるが、「本人の行は本人だけが編集する」を表計算の権限で守るには、行ごとの保護をメンバーごとに設定し続けることになる。role を持つことで出せる差がここにある
- **製品の原則: 評価に転用できない**
  - レベルと学びたいは本人だけが付ける。管理者も他人の行を編集できない
  - 人ごとの合計・ランキング・エクスポートを作らない。チームとしての姿 (偏り、スキルごとの学びたいの人数) だけを見せる
  - スキルはチームごとに持ち、事業所全体で共通のスキル表を作らない
- **taimei-auth との分担**: 招待の作成・判定・受諾はすべて taimei-auth が担う。taimei は招待について何も判断せず、taimei-auth のメンバー画面へのリンクを出すだけにする
- **受け入れ条件**: 次の 7 場面がすべて成り立てば、事業所単位で運用できたとみなす。それまで数値の KPI は置かない
  1. 事業所を作った人が、作成後に taimei の `/dashboard` に入れる
  2. taimei から招待された人が、受諾後に taimei に入り、招待された事業所の画面を見る
  3. role によって taimei で使える操作が変わる (管理者だけがチーム・スキル・割り当てを管理できる。SDK が role を返さない時は権限なしとして扱う)
  4. taimei が現在の事業所のメンバー一覧を表示できる
  5. 事業所を切り替えても、別の事業所のデータが見えない
  6. 除名・退会した人は、次のリクエストから元の事業所のデータにアクセスできない
  7. 除名・退会・事業所削除の後、taimei 側のその人・その事業所のデータが物理削除される

## Considered Options

- **invoice ドメインを製品に育てる**: チュートリアル由来で、事業所の仕組み (role、メンバー単位のデータ) を使う場面が無い
- **管理者だけがログインする星取表**: 作るものは少ないが、事業所の membership と role を使わず、肝を確かめられない
- **作る前に需要を検証する**: 確かめたいのは事業所単位の運用で、作らないと確かめられない

## Consequences

- 7 場面のうち 2・4 は、taimei-auth の変更 (招待後の戻り先、メンバー一覧の RPC) が入るまで成り立たない。7 には、メンバーが抜けたことを taimei が taimei-auth から知る仕組みが要る
- 他人の個人情報 (メンバーの自己申告) を預かる。誰でも taimei-auth で事業所を作って taimei に入れ (場面 1)、使える事業所を限る段階は設けない (2026-10-06 に改めた。当初は物理削除などが済むまで自分以外が使い始められない仕組みを置く予定だった)。物理削除、プライバシーポリシー、データの保存場所の開示、RLS (ADR-0002 の「最初の実顧客受入前」の前倒しトリガー) は、レベルの保存を始めた後に入れる
- 星取表は今の値だけを持ち、履歴を持たない。要るようになったら変更ログを後から足す
